List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |

| 1 | `compute_late_minutes` (lines 36-37) | Pre-truncation of minutes before grace check: `int(seconds / 60)` truncates to 10 for 601s, failing `minutes > 10` and returning 0 instead of 10. | Punch-in at 09:40:01 for a 09:30 shift. R2 states 09:40:01 gives 10, but starter returns 0. | Check total seconds strictly: `diff_sec > 600`, then compute `int(diff_sec // 60)` floor. |
| 2 | `compute_late_minutes` (lines 33-35) | Timezone naive/unaware replacement: `punch_in.replace(hour=h, minute=m)` fails when `punch_in` is in UTC and shift times are in IST. | Run server in UTC or provide UTC timestamp. Comparing local naive time with IST produces an offset error of 5.5 hours. | Convert punch instant to IST timezone (`UTC+05:30`) and construct shift start datetime in IST. |
| 3 | `compute_late_minutes` (lines 33-37) | Fails to consider overnight shifts when a late punch-in occurs after midnight (e.g. 00:05 for a 22:00 shift). | Employee on 22:00-06:00 shift punches in at 00:05 IST next day. Starter calculates difference against next day's 22:00 start (negative time). | Determine attendance date according to R1, anchoring shift start on the attendance date. |
| 4 | `compute_work_hours` (line 41) | Uses Python's built-in `round()`, which performs round-half-to-even (banker's rounding) instead of required round half-up. | Work duration resulting in 8.125 hours rounds to 8.12 instead of 8.13. | Used `decimal.Decimal` with `ROUND_HALF_UP` to round to 2 decimal places. |
| 5 | `compute_overtime` (line 47) | Ignores the minimum 30-minute qualification threshold (R3). | Employee punches out 15 minutes after shift end. Contract requires `overtime_minutes = 0`, but starter returns 15. | Return whole minutes elapsed only if `minutes >= 30`, otherwise return 0. |
| 6 | `compute_overtime` (line 46) | Sets `end` datetime on `date_str`, breaking overnight shifts where shift end falls on the next calendar day (`date + 1 day`). | Overnight shift 22:00-06:00 on 2026-07-06 punches out at 06:40 on July 7. Starter computes `end` on July 6, yielding ~1480 min overtime instead of 40. | Check if `shift_end <= shift_start`; if so, shift end date is `date + timedelta(days=1)`. |
| 7 | `health` (lines 72-74) | Returns `{"status": "ok"}` unconditionally without checking MongoDB connection. | Stop MongoDB or provide an invalid URI; `/health` returns 200 instead of 503. | Added `client.admin.command('ping')` inside a try-except block, raising HTTP 503 if unreachable. |
| 8 | `create_employee` (lines 79-83) | Check-then-insert race condition allows duplicate `emp_code` under concurrent requests. | Send concurrent POST requests with the same `emp_code`. | 9 | `create_employee` (lines 53-60, 78) | Missing validation that `shift_start` must differ from `shift_end` (per OpenAPI contract). | POST `/employees` with `shift_start: "09:00"` and `shift_end: "09:00"` returns 201 instead of 422. | Added model validator in `EmployeeCreate` raising `ValueError` when shifts are identical. |
| 10 | `create_employee` (lines 82-85) | `created_at` set to naive `datetime.now()` and serialized as an ISO-8601 string instead of integer epoch milliseconds. | Inspect response body: `"created_at"` is a string timestamp rather than an integer int64 epoch ms. | Stored UTC BSON datetime in MongoDB and converted to integer epoch milliseconds in serializer. |

| 14 | `punch_in` (lines 104-118) | Check-then-insert race condition on `(emp_code, date)`. | Two concurrent punch-ins for the same employee and date both insert duplicate records. | Created a unique compound index on `("emp_code", 1), ("date", 1)` and catch `DuplicateKeyError` -> 409. |
| 15 | `punch_in` (lines 101, 113) | Unhandled `TypeError` (HTTP 500) if employee does not exist (`emp` is None). | POST `/attendance/punch-in` with non-existent `emp_code`. Server returns 500 Internal Server Error. | Added check: `if not emp: raise HTTPException(404, "Employee not found")`. |

| 20 | `list_attendance` (lines 136-141) | Missing validation for `date_from > date_to` (contract requires 422). | Request `/attendance?date_from=2026-07-10&date_to=2026-07-01`. | 21 | Application startup | No indexes created at startup; all queries default to collection scans (`COLLSCAN`). | Explain output shows `COLLSCAN` and operations degrade under concurrency and volume. | Added `init_indexes()` creating all unique and compound indexes idempotently during startup lifespan. |

### Also examined and decided was NOT a defect:
1. **Identifier convention (`emp_code` vs `_id`):** The starter consistently uses `emp_code` to identify employees and records rather than MongoDB's internal `_id`. This aligns exactly with the assignment specification ("`_id` is internal and never appears in a request or response; an attendance record is addressed by `(emp_code, date)`").
2. **Environment loading:** `load_dotenv()` loads local configuration while preserving `os.getenv` priority for real injected environment variables, satisfying the environment precedence rule.
3. **Empty history on punch-in:** Setting `history: []` upon punch-in is intentional: history is reserved strictly for manual corrections made via the `PATCH` endpoint, not regular punches.
